# Architecture Overview

PCG CC is a Rust monorepo with a React frontend, structured as a Cargo workspace with 17 crates. The system runs as a single Axum HTTP server that serves both the REST API and the frontend, with separate MCP server binaries for AI agent integration.

## Key data flows

### Task execution flow

<Steps>
  <Step title="Task created">
    A task is created via the UI, MCP tool, or API. It belongs to a project and optionally to a board.
  </Step>
  <Step title="Agent assignment">
    Topsi's `route_task` analyses the topology graph — agent capabilities, current workload, and health — to select the best agent.
  </Step>
  <Step title="Worktree isolation">
    The `WorktreeManager` creates an isolated git worktree for the task attempt. Each execution gets its own branch.
  </Step>
  <Step title="Executor runs">
    The pluggable executor system (Claude, Gemini, etc.) runs the coding agent within the worktree. Logs stream to the frontend via SSE.
  </Step>
  <Step title="Review and merge">
    The diff is available for review. On approval, changes merge back to the base branch. VIBE costs are recorded.
  </Step>
</Steps>

### MCP integration flow

AI agents (Claude Code, Cursor, etc.) connect to PCG CC via the Model Context Protocol:

```
AI Agent ──stdio──▶ MCP Task Server ──▶ SQLite
                    (24 tools, 7 resources)

AI Agent ──stdio──▶ MCP Topsi Server ──▶ SQLite
                    (10 topology tools)
```

Each MCP server runs as a separate binary (`mcp_task_server`, `mcp_topsi_server`) communicating over stdio. The servers are user-scoped — each connection has a user identity and project access is enforced.

## Design principles

1. **Single binary deployment** — the server, all routes, and the frontend compile into one binary. No microservice overhead.
2. **Embedded database** — SQLite means zero database infrastructure. The database file ships with the binary.
3. **Type-safe boundary** — Rust structs generate TypeScript types via `ts-rs`. The `shared/types.ts` file is the contract between backend and frontend.
4. **MCP-first agent interface** — AI agents interact through the standardised Model Context Protocol, not custom APIs.
5. **Topology-aware orchestration** — task routing, team formation, and health monitoring use a live graph model, not static assignment.
