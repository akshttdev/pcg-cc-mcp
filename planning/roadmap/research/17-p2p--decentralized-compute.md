## 3. Token Economics for Compute Networks

**Successful models in production:**

- **Akash BME (Burn-Mint Equilibrium):** Tenants pay in USD-pegged ACT credits (generated by burning AKT). ACT burned at settlement, AKT re-minted to providers at current price. If burns > mints, AKT becomes deflationary. Helium validated this model -- HNT became net deflationary as adoption grew. Providers can optionally auto-stake a % of payouts.

- **Render:** Work token model -- node operators stake RENDER to receive rendering/inference jobs. Payment flows through the token.

- **Nosana:** NOS token for job payments on Solana smart contracts. Automatic matching of supply/demand, on-chain rewards for GPU hosts.

- **Bittensor (TAO):** Market-driven resource allocation via dTAO upgrade (late 2025). Specialized AI subnets compete for TAO emissions based on performance.

- **Golem (GLM):** Dual-purpose token for compute + data (via Arkiv). Expanding utility beyond raw compute.

**Key patterns:** The most successful models tie token demand directly to network usage (not speculation). Burn mechanisms linked to actual compute consumption create sustainable economics. USD-denominated pricing with on-chain token settlement is the emerging standard.

**Staking landscape:** Global staking market >$245B. Liquid staking is ~40% of DeFi TVL ($37.8B). SEC cleared protocol-level staking as non-securities (May 2025).

## 4. libp2p

**Current state:** Mature and production-deployed. Recommended version v0.42+.

**Production adoption:**
- Algorand migrated to native P2P using go-libp2p, removing centralized relay dependency. Running in production since 2025; all consensus/voting data via libp2p by Q3 2026.
- IPFS, Filecoin, Ethereum (via devp2p/libp2p), Polkadot all use libp2p in production.
- Reticulum (mesh networking stack) uses libp2p-style identity model.

**Strengths:** Multi-transport (TCP, QUIC, WebRTC, WebSocket), peer discovery (mDNS, DHT, rendezvous), NAT traversal (hole punching, relay), protocol multiplexing, mature Rust/Go/JS implementations.

**Alternatives:**
- **Hypercore Protocol (v12.3+)** -- recommended alongside libp2p for production P2P stacks.
- **ZeroMQ** -- lower-level, no built-in peer discovery.
- **Matrix/libp2p hybrid** -- some projects combine Matrix for messaging with libp2p for data.

**For APN:** libp2p is the de facto standard for P2P mesh networking in production. Its Rust implementation (rust-libp2p) integrates naturally with a Rust backend. NAT traversal and multi-transport support are critical for consumer desktop nodes.

## 5. NATS Messaging

**Architecture:** Distributed mesh topology (vs MQTT's central broker). Single binary, minimal resources, sub-millisecond latency.

**Key advantages over alternatives:**
- **vs MQTT:** NATS has native horizontal scaling, built-in message queueing, message streams (JetStream), distributed state. MQTT is hub-and-spoke, stateful by design, no native clustering.
- **vs gRPC:** NATS is pub/sub (push), gRPC is request/response (pull). NATS has built-in HA/FT via full mesh clustering with self-healing. gRPC requires external infrastructure for HA.
- **vs RabbitMQ:** NATS is simpler operationally (single binary), better horizontal scaling, lower latency.

**Performance:** Millions of messages/second at micro-to-low-millisecond latency.

**Features:** Pub/sub, request/reply, streaming with persistence (JetStream), all through a single binary.

**For APN:** NATS is ideal for mesh network inter-node communication. Its distributed mesh topology mirrors the network architecture. JetStream provides persistence for job queues. Request/reply pattern works for compute task distribution. Single binary simplifies node deployment.

## 8. Regulatory Considerations

**Major positive developments for token-based compute networks:**

- **SEC/CFTC Joint Framework (March 17, 2026):** Five formal categories for digital assets established. 16 major tokens classified as "digital commodities" under CFTC (not SEC). Ends decade of jurisdictional ambiguity.

- **Protocol Staking Cleared (May 29, 2025):** SEC Division of Corporation Finance: on-chain staking of digital commodities does NOT create securities transactions. No registration required for protocol-level staking.

- **Liquid Staking Also Cleared (August 2025):** SEC clarified liquid staking activities are not securities transactions.

- **Utility Token Safe Harbor:** Tokens without inherent rights to passive income, business enterprise interest, or profit distribution are NOT securities. This is directly relevant for compute utility tokens.

- **Tokenized Securities Guidance (January 28, 2026):** SEC issued comprehensive guidance. Key principle: technology/format doesn't change regulatory perimeter -- substance matters.

- **Formal Rulemaking Coming:** SEC proposals expected in 2026 for comprehensive crypto asset framework and exchange/ATS amendments.

**For APN:** The regulatory environment is the most favorable it has ever been. A utility token used for compute payments (not profit-sharing) with protocol-level staking falls clearly outside securities classification under current guidance. The BME model (Akash) or work-token model (Render) both appear compliant.

## 9. Ed25519 / X25519 / BIP39

**Current best practices for P2P identity and encryption:**

- **Identity:** Ed25519 signing key (256-bit) + X25519 encryption key (256-bit) = 512-bit keyset per identity. This is the standard pattern (used by Reticulum, Signal, many P2P systems).
- **Stream encryption:** XChaCha20-Poly1305 for data, Ed25519 for peer identity/signing.
- **Key exchange:** X25519 Diffie-Hellman. Post-quantum upgrade path: SPQR (Triple Ratchet) combines X25519 with CRYSTALS-Kyber.
- **Recovery:** BIP39 mnemonic phrase for key derivation. Versioned metadata object encrypted with BIP39-derived key, backed up to DHT for bare-metal recovery.
- **SSH/general:** Ed25519 is the recommended default (over RSA/ECDSA P-256).
- **Key management:** HSMs for production key storage, key rotation policies for long-lived keys.
- **Post-quantum consideration:** MLS (Messaging Layer Security) and SPQR protocols are becoming standard for forward-looking E2E encryption.

**For APN:** Ed25519 + X25519 + BIP39 is the correct stack. This is mature, well-understood, and the de facto standard. BIP39 recovery phrases give users sovereignty over their node identity. The post-quantum upgrade path (Kyber) is available when needed.
